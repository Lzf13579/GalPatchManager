# 游戏补丁安装器

**版本 1.0.0**

一个 Windows 10/11 桌面程序：**发现已安装的 Galgame → 查找补丁网址 → 监控下载 → 自动导入/安装补丁**。

技术栈：**C# / .NET 8 / WinForms**。项目结构参考了 [PCL2（Plain Craft Launcher 2）](https://github.com/Hex-Dragon/PCL2) 的组织方式
（`Mod*` 核心服务 + `Page*`/`*Tab` 页面 + `SettingService` 风格的集中配置），但代码全部为本项目重写。

## 1. 快速开始

要求：**Windows 10/11 x64** + **.NET 8 SDK**（编译）或 **.NET 8 Desktop Runtime**（仅运行）。

```powershell
git clone <this-repo>            # 或直接解压
cd GalPatchManager

# 一键构建 + 自检 + 打包
powershell -ExecutionPolicy Bypass -File build.ps1 -Configuration Release -Publish
```

产物在 `publish\`，双击 `GalPatchManager.exe` 即可运行。

等价的原生命令：

```powershell
dotnet build   src\GalPatchManager\GalPatchManager.csproj -c Release
dotnet publish src\GalPatchManager\GalPatchManager.csproj -c Release -r win-x64 --self-contained false -o publish
```

首次启动后建议按这个顺序操作：

1. **设置** → 确认「下载目录」。默认是本程序自己的 **`%AppData%\GalPatchManager\DropFolder`**（「放这里」文件夹），
   **不是**系统「下载」目录——因为系统下载目录通常堆满软件安装包，会把待处理列表刷爆。
   保持「启用下载目录监控」开启，点「保存设置」。
   （如果之后你调小了体积下限，记得先点「重新建立基线」清掉积压的小文件，理由见 [4.3 节](#43-下载监控与补丁安装待处理补丁页)。）
2. **游戏列表** → 点「刷新列表」，程序会自动扫描 Steam 全部库；Steam 之外的游戏用「手动添加游戏」加入。
3. **查找补丁** → 选择游戏 → 「查找补丁」。默认是浏览器搜索方式，不会有假结果；配置 SearXNG 后可自动列出候选网址。
4. 把补丁下载/拖到监控目录，程序只识别**新增**文件并自动判定下载完成，随后出现在 **待处理补丁** 页。
5. **待处理补丁** → 确认匹配的游戏 → 「解压并预览」→「安装到游戏」。

## 2. 构建与打包

### 2.1 一键打包成单个 .exe 和分发包 zip（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File package.ps1
```

脚本会依次执行 **构建 → 自检 → 自包含单文件发布 → 组装 → 压缩**，任一步失败即中止。

产物：

```
dist\
├─ GalPatchManager-v1.0.0-win-x64\
│  ├─ GalPatchManager.exe     ← 唯一可执行文件（约 69 MB）
│  └─ 使用说明.txt
└─ GalPatchManager-v1.0.0-win-x64.zip   ← 分发包（约 63 MB）
```

| 参数 | 说明 |
| --- | --- |
| `-OutputDir <dir>` | 输出目录，默认 `dist` |
| `-Runtime win-x64` | 运行时标识 |
| `-Compress $false` | 不做单文件内部压缩（体积更大、首次启动更快） |
| `-DotnetPath <path>` | 显式指定 `dotnet.exe` |
| `-SkipSelfTest` | 跳过自检（不推荐） |

> **为什么单个 exe 有 69 MB？**
> 真正的单文件必须**自包含**发布：框架依赖模式下 `SharpCompress.dll`、`ZstdSharp.dll` 会作为独立文件留在 exe 旁边，
> 无法整合进单个文件。自包含把一个完整的 .NET 运行时打进 exe，换来的是**目标机器无需安装 .NET**。
> 如果你希望体积小且能接受目标机预装 .NET 8 桌面运行时，改用 `build.ps1 -Publish`（产物约 1.3 MB + 两个 dll）。

### 2.2 常规构建

`build.ps1` 会依次执行：**还原 → 构建 → 自检 → 发布**，任一步失败即中止（不会产出"看起来成功"的包）。

| 参数 | 说明 |
| --- | --- |
| `-Configuration Debug\|Release` | 构建配置，默认 `Debug` |
| `-Publish` | 额外执行 `dotnet publish` |
| `-SelfContained` | 自包含发布，目标机器无需安装 .NET（体积大很多） |
| `-SingleFile` | 单文件发布（需配合 `-SelfContained`） |
| `-Runtime win-x64` | 运行时标识，默认 `win-x64` |
| `-DotnetPath <path>` | 显式指定 `dotnet.exe` |
| `-SkipSelfTest` | 跳过自检（不推荐） |
| `-OutputDir <dir>` | 发布目录，默认 `publish` |

常用组合：

```powershell
# 日常开发
.\build.ps1

# 分发给已装 .NET 8 桌面运行时的用户（推荐，体积小）
.\build.ps1 -Configuration Release -Publish

# 完全自包含的单文件版本（约 150 MB）
.\build.ps1 -Configuration Release -Publish -SelfContained -SingleFile
```

> **脚本编码注意**：`build.ps1` 与 `package.ps1` 都带 UTF-8 BOM。Windows PowerShell 5.1 会把无 BOM 的 UTF-8
> 当成本地代码页读取，中文注释会导致语法错误。如果你编辑这些脚本，请保持 BOM，或改用 PowerShell 7+。
> 同理，脚本内部读取 `.csproj` 时显式用了 `-Encoding UTF8`，否则中文注释会被读成乱码导致 XML 解析失败。

## 3. 自检

程序内置自检模式，覆盖核心逻辑，全部在临时目录中进行，**不会碰你的真实游戏目录**：

```powershell
dotnet src\GalPatchManager\bin\Release\net8.0-windows\GalPatchManager.dll --selftest
# 退出码 0 = 全部通过；1 = 有失败项

# 指定启动页（用于排查问题）：--tab=设置 / --tab=downloads / --tab=待处理补丁

# 测试 Steam 接口连通性（排查「归类联网失败」）：
dotnet ...\GalPatchManager.dll --nettest
#   会逐个网络策略（直连 / 系统代理 / 自定义代理）试一遍，
#   结果写入 %AppData%\GalPatchManager\nettest.txt
```

报告生成在 `%AppData%\GalPatchManager\selftest-result.txt`。

当前覆盖 **176 项检查**，包括：

| 分组 | 覆盖内容 |
| --- | --- |
| VDF / ACF 解析 | 嵌套库写法、老版扁平写法、ACF 字段、畸形输入不崩溃 |
| 游戏类型 | 解析优先级（手动 > 自动 > 未分类）、Steam 条目重建后类型保留、自定义类型进菜单、数量统计、Ren'Py/KiriKiri/RPG Maker 引擎识别、普通目录不误判 |
| 类型映射与归类 | genre 映射优先级、appdetails JSON 离线解析、success=false 与非法 JSON 容错、归类优先级（手动 > genre > 引擎 > 名称 > 未分类）、**离线且无特征时不谎报类型**、**缓存 genres 可离线完成归类**、**名称关键词可完全离线归类**、名称规则可开关、标签缓存读写与清除 |
| 补丁与游戏匹配 | AppID（含 `appmanifest_123`、`appid=123`、`[123]`）、用户关键词、匹配规则、CJK 二元组模糊匹配、避免误判 |
| 哈希与完整性 | SHA-256 正确性、被独占锁定的文件判定为不可读 |
| 压缩包 | ZIP 解析、根目录识别与剥离、中文文件名、**路径穿越被拒绝**、损坏包不崩溃 |
| 下载监控 | `.crdownload/.part/.tmp/隐藏文件` 忽略、稳定判定、**等长内容变化不误判**、**持续增长不误判**、静默时长门槛、**只处理新增文件（基线过滤）**、**多轮扫描仍能完成判定（基线不得提前拦截）**、**完成后不重复触发**、**最小体积过滤** |
| 安装 | 计划生成、覆盖前备份、备份内容正确、无临时文件残留 |
| 备份还原 | 备份 → 覆盖 → 还原回原内容 |
| 失败回滚 | 中途失败 → 新增文件被删除 → 被覆盖文件被还原 → **不报告为成功** |
| 重复安装 | 补丁键稳定性与去重判定 |
| EXE 可信规则 | 无规则不可信、仅文件名不算可信、哈希校验、静默参数、自动运行必须显式开启、运行器拒绝非 exe |
| 路径安全 | `..`、盘符、UNC、绝对路径、`./` 全部拒绝 |
| 搜索服务 | **绝不伪造结果**、无配置时明确报错并回退浏览器、白名单匹配（含子域） |

## 4. 功能说明

### 4.1 游戏检测（游戏列表页）

左侧「游戏列表」下带**二级菜单**，按游戏类型筛选：

```
游戏列表
  全部 (49)
  视觉小说 (12)
  冒险
  角色扮演 (3)
  ...
  未分类 (30)
查找补丁
待处理补丁
安装历史
设置
```

- 条目后面的数字是该类型下的游戏数量（0 个时不显示数字）。
- 点二级项即在「游戏列表」页内筛选；再点「游戏列表」标题或「全部」可清除筛选。
- **类型来源说明（重要）**：类型**不可能完全自动准确识别**，实际规则是五层，优先级从高到低：
  1. **用户手动指定**（最高优先级，持久化，Steam 游戏刷新后仍保留）；
  2. **Steam 社区标签映射（识别「视觉小说」的关键一层）**：
     官方 appdetails 接口**只有 genres，没有社区标签**；而 `Visual Novel`/`Dating Sim`/`Otome`
     这些正是社区标签。实测确认商店页标签是 JS 异步渲染的，HTML 取不到；
     但**搜索接口** `/search/results/?json=1&term=<游戏名>` 返回的每项都带
     `data-ds-tagids="[3799,9551,...]"`，即该游戏的完整社区标签 ID 列表。
     本程序据此抓取标签，再用可配置的 `TagTypeMapping`（设置页「游戏归类」可改）折算成类型。
     默认 `Visual Novel`/`Dating Sim`/`Otome` → 视觉小说。开关：`抓取 Steam 社区标签`（默认开启）。
     为避免遗漏，抓取按**三级 fallback** 依次尝试：
     ① 用**游戏名**搜索（最精确）→ ② 用 **AppID** 搜索（名字特殊/多语言时仍能命中）
     → ③ 抓**商店页 HTML** 兜底（实测标签是 JS 渲染的，通常取不到，仅作最后尝试）。
     实测：只按游戏名时 30/49 命中，加入 AppID fallback 后提升到 **48/49**。
  3. **Steam 官方类型（genres）映射**：联网调用官方公开接口
     `store.steampowered.com/api/appdetails?appids=<id>` 取 genres（Action / Adventure / RPG / Indie…），
     再按**可配置的映射表**（设置页「游戏归类」可改）转成本程序类型。
     结果缓存到 `steam-appinfo.json`，默认 14 天内不重复请求；**断网时用缓存或直接跳过**。
     映射表**顺序即优先级**：默认 `Adventure → 冒险`、`RPG → 角色扮演`、`Action → 动作`、
     `Strategy → 策略`、`Simulation → 模拟`、`Casual → 休闲`、`Indie → 独立`。
  4. **游戏名 / 目录名关键词**（纯离线，不依赖网络）：按可配置的关键词表匹配，
     例如 `ビジュアルノベル`/`ノベルゲーム`/`ギャルゲー` → 视觉小说、`ADV` → 冒险、`RPG` → 角色扮演。
     规则表在设置页「游戏归类」里可直接增删改。
  5. **本地引擎特征识别（最后手段）**：扫描安装目录，例如 `script.rpy/.rpyc` → 视觉小说（Ren'Py）、
     `.xp3`/`krkr.exe` → 视觉小说（KiriKiri）、`.rvdata2`/`.rgssad` → 角色扮演（RPG Maker）、
     `unityplayer.dll` → 其他（Unity）。
  - 都没有 → **未分类**。
  - ⚠️ **引擎识别必须排在 genres 之后**：它只能判断"技术栈"（是不是 Unity），判断不了玩法类型。
    早期版本把它排在 genres 前面，导致所有 Unity 游戏被盖成「其他」，明明有
    `Adventure`/`RPG` 这种更有用的官方类型却没用上。
- ⚠️ **关于「标签」的实话**：Steam 官方接口**只提供 genres，不提供社区用户标签**
  （Visual Novel / Anime / Gore 这些是社区标签，没有官方 API）。所以本功能是
  **「按官方类型 + 本地引擎特征」归类，不是按用户标签**。程序不会假装能读用户标签。
- **联网方式（代理相关，重要）**：设置页「游戏归类」里可选
  | 模式 | 行为 |
  | --- | --- |
  | `Auto`（默认） | **先直连，失败再试系统代理** |
  | `Direct` | 只用直连，不使用代理 |
  | `SystemProxy` | 只使用系统代理设置 |
  | `CustomProxy` | 只用你填写的代理地址（如 `http://127.0.0.1:7897`） |
  - **为什么默认先直连**：实测发现装了 Clash Verge 这类代理软件时，系统代理虽然能建立 CONNECT 隧道
    （返回 `200 Connection established`），但**隧道内的 TLS 握手会失败**
    （`Received an unexpected EOF`），而**直连反而正常**。强制走系统代理会让所有元数据请求全部失败
    —— 这正是「归类不生效」的根因。
  - 归类前会先做**一次连通性探测**：网络不通就立刻放弃联网部分、只用本地识别并弹窗说明原因；
    **不会对每个游戏都等超时**（否则几十个游戏要卡好几分钟）。
  - 设置页有「**测试连接**」按钮，会逐个策略试一遍并如实报告结果。
- 操作方式：
  - 「**自动归类（按类型）**」按钮：对全部游戏跑上述三层规则，弹窗报告各类来源数量；
    **绝不覆盖**你手动指定的类型。
  - 详情区「类型」下拉框：可选项内置类型，也能**直接输入自定义类型**（如「悬疑」），
    回车或失焦即保存；「应用类型到选中」可批量设置多选行。
- 自动结果在列表里标注「（自动）」，类型列还会附带原始 genres（如 `冒险（自动） · Adventure/Indie`），
  方便核对归类依据。
- **其他识别能力：**- **Steam 自动识别**，不局限于默认库：
  1. 注册表定位 Steam 根目录（`HKCU\Software\Valve\Steam\SteamPath` / `SteamExe`，`HKLM\...\Valve\Steam\InstallPath`，以及常见默认路径）；
  2. 读取 `steamapps\libraryfolders.vdf` 得到**全部**库路径，同时兼容新版嵌套写法与老版扁平写法（还兜底读 `config\libraryfolders.vdf`）；
  3. 合并用户手动补充的额外库路径；
  4. 解析每个库 `steamapps\` 下所有 `appmanifest_*.acf`。
- 列表显示 **游戏名称 / Steam AppID / 安装目录 / 来源 / 说明**。
- 支持 **刷新列表**、**搜索过滤**（名称 / AppID / 路径）。
- 支持 **修正识别结果**：改名、改目录、加关键词。Steam 游戏的修正会保存为手动条目并隐藏原条目（不破坏 Steam 数据）。
- 手动添加游戏，或从列表**移除/隐藏**。
- 同一游戏出现在多个库时按 AppID 去重，优先保留目录真实存在的那份。
- 库路径不存在等异常会作为诊断信息记录到日志，不影响其他库的扫描。

### 4.2 查找补丁（查找补丁页）

- 从游戏列表选择，或直接输入游戏名。
- 关键词模板可配置，默认 `{0} 汉化补丁` / `{0} 中文补丁` / `{0} 修复补丁` / `{0} 汉化 patch`。
- 三种搜索方式：
  | 方式 | 说明 |
  | --- | --- |
  | `Browser`（默认） | 不调用任何接口，生成 Bing / Google / Bilibili / 百度搜索链接，在浏览器中打开。**无需 API Key** |
  | `Searxng` | 自建 SearXNG 实例，需在实例 `settings.yml` 开启 `json` 格式输出；可点「测试连接」 |
  | `CustomJson` | 任意返回 JSON 的搜索接口，URL 模板必须含 `{query}`；支持 API Key 放 Header 或 Query；可指定结果数组路径（如 `data.items`），否则自动探测 `results/items/data/organic_results/web/hits` |
- 结果展示 **标题 / 网址 / 来源网站 / 是否白名单 / 引擎 / 简要说明**；支持在浏览器打开、复制网址、导出候选列表。
- **搜索结果只是候选网址**：`PatchCandidate.IsVerified` 恒为 `false`，界面不会把它当作已验证的补丁文件。
- **白名单**：可加域名（含子域匹配）或完整网址，命中后标记为「白名单」候选。白名单只表示「这个来源你信任」，不等于该网址就是可用补丁。
- **没有配置搜索服务时，程序不会伪造任何结果**，只提供浏览器搜索入口。
- 自定义接口做了 SSRF 防护：拒绝解析到内网/环回/链路本地地址的目标（SearXNG 显式允许 localhost，因为自建实例通常在本机）。

### 4.3 下载监控与补丁安装（待处理补丁页）

**监控目录与「只处理新增文件」**

监控目录默认是本程序自己的 **`%AppData%\GalPatchManager\DropFolder`**（「放这里」文件夹），不是系统「下载」目录。
系统下载目录里通常堆满 `SteamSetup.exe`、`VC_redist.x64.exe` 这类软件安装包，直接监控会把待处理列表刷爆。

开启「只处理新下载的文件」（默认开启）后：

- 目录**第一次**被监控时，其中已有的文件全部登记为「基线」并忽略，一个都不处理；
- 之后只有**新增**或**内容有变化**（大小 / 修改时间变了）的文件才进入待处理列表；
- 程序关闭期间下载的补丁也不会漏：它的修改时间晚于基线建立时间，下次打开仍会被识别；
- 设置页显示基线状态（建立时间 + 已忽略数量），并提供「重新建立基线」「清除基线」按钮，以及「打开监控目录」按钮（目录不存在时会自动创建）。
- 文件**判定完成后**才登记进基线，因此「稳定判定」可以正常累积多次扫描；重复扫描也不会重复触发。

另有「最小体积过滤」（默认 1 MB），挡掉 `.url` / 说明文件 / 空壳文件。

> **重要提示：调小体积下限后，请先「重新建立基线」**
>
> 体积过滤发生在基线判断之前：**小于下限的文件既不会进入列表，也不会被登记进基线**。
> 所以如果你把下限从 1 MB 调成 0 或更小，下载目录里原本被过滤掉的积压小文件会**一次性全部冒出来**，
> 把待处理列表刷满。正确做法是：改完设置后先点设置页的「重新建立基线」，把这些小文件一次性登记为
> 「已存在」，之后只处理真正新增的补丁。

关闭该开关则会像老版本一样列出目录内所有匹配文件——适合把监控目录专门当作补丁暂存目录使用。

**判定下载完成的三重条件（缺一不可）：**

1. 扩展名属于补丁类型，且不在忽略列表 —— `.crdownload` / `.part` / `.tmp` / `.partial` / `.!ut` 等临时文件，以及隐藏文件直接跳过；
2. 文件大小**连续 N 次**（默认 3）完全不变，**且**已经静默足够长时间（默认 2 秒）；
3. 文件**能够被完整读取**：独占打开成功、可读到内容、长度与文件系统一致；压缩包还要能正常打开。

此外还做了两道额外保护：

- 计算 SHA-256 期间文件若再次变化 → 继续等待；
- 内容哈希与上次不同（大小/时间戳都没变的等长改写）→ 重新计数。

**匹配游戏**：顺序为 `AppID 命中 → 用户关键词/规则 → 名称模糊匹配`；置信度不足时不自动认定，而是显示「低置信度候选」并让用户手动选择。

**压缩包安装（.zip / .7z / .rar）**：

- 用 SharpCompress 纯托管解析，**无需外部 7z.exe**；
- 自动识别压缩包是否有统一根目录：有则剥离（可理解为「把压缩包内容铺进游戏目录」），没有则原样铺开；
- 先解压到 `%AppData%\GalPatchManager\Temp\<id>`，**不会直接写游戏目录**；
- 界面完整展示「将复制的文件」清单（新增/覆盖、相对路径、大小、被拒绝的条目）；
- 覆盖前**自动备份**到 `%AppData%\GalPatchManager\Backups\<批次>\`；
- 写入采用「先写 `.galpatch-new` 再原子替换」，避免中途失败留下半截文件；
- 任一步失败 → 记录具体错误 → 删除本次新增文件 + 还原被覆盖文件（回滚）→ **失败绝不报告为成功**。

**EXE 补丁**：

- 支持自动安装，但**只有满足全部条件**才自动运行：
  1. 命中用户配置的可信规则；
  2. 规则的 **SHA-256 白名单**或**来源域名白名单**校验通过（**只有文件名通配不算可信**）；
  3. 规则里**显式配置了静默安装参数**；
  4. 用户在设置里显式开启了「允许自动运行可信 EXE」并关闭了「始终要求确认」。
- **程序绝不猜测静默安装参数**（不会自己拼 `/S`、`/silent` 之类）。
- 其他 EXE 一律弹窗让用户确认后才运行。
- 运行使用 `UseShellExecute = true`，因此 **Windows 自身的 UAC / SmartScreen 提示照常出现，程序不绕过**。
- 等待进程结束并检查退出码；非 0 退出码会如实报告为未成功。
- 设置页提供「计算选中 EXE 的 SHA-256」方便你把哈希加进规则。

**去重与历史**：

- 补丁键 = `文件名 + 大小` 的短哈希；命中历史中的成功记录即提示「已安装过」。
- 安装历史记录：时间、游戏、补丁文件、方式、结果、文件数、字节数、SHA-256、备份批次、错误说明。
- 可在历史页查看详情、打开备份目录、**一键还原该批次备份**、导出 CSV（带 BOM，Excel 打开中文不乱码）、清空历史。

### 4.4 设置页

- **下载监控**：目录、启用开关、轮询间隔、稳定判定次数、最短静默秒数、忽略的临时扩展名。
- **安装与备份**：覆盖前备份、失败自动回滚、备份保留天数、安装后归档补丁文件。
- **搜索服务**：方式选择、SearXNG 地址 + 测试连接、自定义接口模板 / API Key / 附加方式 / 结果路径、关键词模板、结果上限、超时。
- **白名单**：域名列表、完整网址列表。
- **可信 EXE 规则**：规则表格（名称、文件名通配、SHA-256、来源域名、静默参数）+ 计算 SHA-256 工具。
- **关键词匹配规则**：关键词 → 对应游戏。
- **日志与数据位置**：打开配置/日志/备份目录、清理临时解压目录。

见上文「去重与历史」。

## 6. 安全设计

| 风险 | 处理 |
| --- | --- |
| 压缩包路径穿越 | 拒绝 `..` / `.` / 盘符 / UNC / 绝对路径 / 非法字符；解压后再用 `Path.GetFullPath` 复核目标必须在目标目录内；检测到不安全条目立即中止解压 |
| 压缩炸弹 | 单条目上限 2 GiB、条目数上限 200,000 |
| 覆盖丢文件 | 覆盖前备份，失败自动回滚 |
| 半截文件 | 临时文件 + 原子替换 |
| 恶意 EXE 自动运行 | 必须命中规则 + 哈希/域名校验 + 显式配置静默参数 + 用户显式开关；默认「始终要求确认」 |
| 提权 | `app.manifest` 使用 `asInvoker`，**不请求管理员权限、不绕过 UAC** |
| SSRF | 自定义搜索接口拒绝环回/私有/链路本地/组播地址，DNS 多记录全部校验 |
| 重复安装 | 补丁键去重 + 安装前二次确认 |
| 静默失败 | 全局异常处理写日志 + 弹窗；失败路径绝不标记成功 |
| 配置文件损坏 | 解析失败自动备份 `config.json.broken-<时间>` 并回落默认值 |

- ✅ 安装计划预览、目录结构保持、覆盖前备份、原子替换、失败回滚、一键还原
- ✅ EXE 可信规则 + 哈希校验 + 静默参数 + 二次确认，不猜测参数、不绕过 UAC

- ✅ 默认监控本程序自己的 DropFolder（不污染系统下载目录），只处理新增文件 + 最小体积过滤
- ✅ 五个界面（游戏列表 / 查找补丁 / 待处理补丁 / 安装历史 / 设置）
- ✅ 内置 176 项自检

### 未实现 / 已知限制

- ❌ **加密压缩包**（带密码的 zip/7z/rar）：会明确报错提示不支持，不尝试破解。
- ❌ **分卷压缩包**（`.part1.rar`、`.7z.001`）：未做合并逻辑。
- ❌ **多语言 / 繁体界面**：界面为简体中文，未做本地化框架。
- ❌ **自动从候选网址下载补丁**：出于安全考虑，程序不自动抓取网页里的文件——需要你确认域名可信并自行下载。这是有意的设计取舍。
- ❌ **搜索服务不做网页抓取**：只调用你配置的 JSON 接口，或打开浏览器；不会解析 HTML 搜索结果页（易被封且不可靠）。
- ⚠️ **`.rar` 为只读支持**：可以解压，但不能生成 rar（本程序也不生成任何压缩包）。
- ⚠️ **补丁去重键为「文件名 + 大小」**，不是内容哈希；同名同大小但内容不同的补丁会被视为同一个，安装前会有二次确认。
- ⚠️ **EXE 补丁无法校验其内部行为**：哈希只证明「文件和你批准过的那份一致」，不证明它安全。请只对你信任的来源配置规则。
- ⚠️ **安装历史不含文件级清单**：还原依赖备份批次目录中的文件名反推原路径，因此**重命名过的文件无法自动还原**（会在历史页给出提示，可手动从备份目录复制）。
- ⚠️ **未做单实例限制**：同时运行多个实例会同时监控同一目录并可能重复处理。
- ⚠️ **未做代码签名**：首次运行可能出现 SmartScreen 提示，属正常现象。

## 9. 常见问题

**Q：刷新后 Steam 游戏列表为空？**
A：日志（`%AppData%\GalPatchManager\Logs\`）里会有 `Steam 诊断` 记录。常见原因是 Steam 装在非标准位置或 `libraryfolders.vdf` 缺失。
可在设置中手动把库路径加入 `ExtraSteamLibraryPaths`，或直接用「手动添加游戏」。

**Q：`.7z` / `.rar` 解压失败？**
A：目前不支持加密包和分卷包。请在界面给出的错误信息中确认具体原因（加密包会提示「需要密码」）。

**Q：为什么配置了搜索接口还是没结果？**
A：程序不会伪造结果。SearXNG 需要在实例的 `settings.yml` 里开启 `json` 输出格式，可用设置页的「测试连接」验证。
自定义接口可用「结果数组路径」明确指定结果位置，例如 `data.items`。

**Q：EXE 补丁为什么不自动安装？**
A：默认「始终要求确认」是开启的，且规则必须同时具备可信来源/哈希与静默参数。这是有意设计——宁可多点一次，也不要让来路不明的安装程序静默执行。

**Q：安装失败后游戏打不开？**
A：先看安装历史页的「结果」列。若显示「已回滚」，说明程序已自动还原被覆盖的文件；
若显示「失败」且未回滚（可关闭「失败时自动回滚」触发），可用历史页的「还原该条备份」手动恢复。
备份默认保留 30 天。

**Q：点了「自动归类」但类型没变 / 全是未分类？**
A：先看弹窗报告里的「元数据请求失败」数量。若是 0 个但结果仍不理想，说明 genres 没匹配到你的映射表，
可在「设置 → 游戏归类」里调整映射。若失败数量很大，是**网络到不了 Steam**：
1. 打开「设置 → 游戏归类」，点「**测试连接**」看具体结果；
2. 试着把「联网方式」从 `Auto` 改成 `Direct`（**最常见的原因就是代理软件破坏了 TLS**），或反之改成
   `SystemProxy`；有可用代理就填 `CustomProxy`；
3. 也可以在「设置 → 下载监控」以外的位置查看日志 `%AppData%\GalPatchManager\Logs\`，
   里面会记录每次探测和失败原因。

网络不可用时归类会退回**本地规则**（引擎特征 + 游戏名关键词），不影响其他功能。

**实测补充（排查时很有用）**：把「联网方式」设为 `Direct` 后如果仍然失败，可以先用一条命令判断
是代理问题还是**网络本身到不了 Steam**：

```powershell
Test-NetConnection store.steampowered.com -Port 443
# TcpTestSucceeded = False  → 连 TCP 都建不起来，属于网络/防火墙层面，
#                              应用侧无论直连还是代理都救不了，请检查代理软件的节点/规则。
# TcpTestSucceeded = True   → 网络可达，失败原因在 TLS 层（多半是代理的 TLS 处理），
#                              换 Direct 或 CustomProxy 通常就能解决。
```

**Q：能改界面语言 / 加新搜索源吗？**
A：搜索源可通过 `CustomJson` 方式接入，无需改代码。界面语言未做本地化框架，需要直接改源码。
